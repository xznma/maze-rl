# maze-rl

完美迷宫 + 钥匙/门，以及两种走迷宫的 agent：算法（BFS + 前沿探索）和强化学习（PPO + LSTM）。

## 迷宫规则

- 递归回溯生成**完美迷宫**（任意两点之间有且仅有一条路径）
- 起点 `S`、终点 `E`；起点到终点的唯一路径中段有一扇门 `D`
- 钥匙 `K` 散落在不穿门就能到达的区域（保证有解）
- agent 只能看到自己四周一格，需要找到钥匙、开门、到达终点

尺寸 `h×w` 指**房间格**数；渲染出来是 `(2h+1)×(2w+1)` 的字符网格，可走格子 `2hw−1` 个。

## 文件

| 文件 | 说明 |
|---|---|
| `maze_game.py` | 迷宫生成、`MazeEnv` 环境、算法 agent，1000/1000 随机迷宫通关 |
| `env.py` | RL 环境包装：25 维局部观测（四周 4 格 + 是否持钥匙 + 上一步动作，无绝对坐标）、奖励设计、向量化环境 |
| `model.py` | Actor-Critic：MLP → LSTM(128) → 策略头 + 价值头，按 episode 边界重置隐状态 |
| `ppo.py` | PPO + LSTM：rollout 采样、GAE、按整条序列做 minibatch、超时 bootstrap |
| `train.py` | 训练主循环 + 七个课程阶段（0–4 局部观测，5–6 地图观测） |
| `eval.py` | 在没见过的迷宫上评估，和算法 agent 并排对比；支持在更大尺寸上零样本测试 |
| `bench.py` | 尺寸泛化基准：多个 checkpoint × 多个尺寸 × 采样/贪心，结果增量写入 `results/` |
| `ckpt/` | 阶段 0–6 训练好的 checkpoint |
| `viz.py` | 生成自包含的网页回放：两个 agent 在同一张迷宫上并排走，带迷雾、轨迹、事件标记 |
| `replay.html` / `replay_8x8.html` | 回放示例，直接用浏览器打开 |

## 运行

```bash
# 算法 agent
python maze_game.py --seed 7 --h 8 --w 16
python maze_game.py --animate          # 终端动画，带迷雾

# PPO + LSTM（需要 pip install torch numpy）
python train.py --stage 0                       # 固定 3x3，无钥匙门：验证代码
python train.py --stage 1                       # 固定 5x5，无钥匙门
python train.py --stage 2                       # 随机 5x5，无钥匙门
python train.py --stage 3 --init ckpt/stage2.pt # 随机 5x5，有钥匙门
python train.py --stage 4 --init ckpt/stage3.pt # 随机 8x8，有钥匙门
python train.py --stage 5                       # 地图观测，随机 5x5（从零）
python train.py --stage 6 --init ckpt/stage5.pt # 地图观测，混合尺寸 5–10
python eval.py ckpt/stage4.pt --episodes 100 --render 3
python eval.py ckpt/stage4.pt --episodes 50 --h 12 --w 12   # 零样本测更大的迷宫
python bench.py ckpt/stage4.pt ckpt/stage6.pt --sizes 5 8 12 16 --json results/x.json

# 网页回放
python viz.py ckpt/stage4.pt --seed 1000010 --out replay_8x8.html
```

## 课程进度

| 阶段 | 设定 | 收敛步数 | 测试结果（100 张没见过的迷宫） |
|---|---|---|---|
| 0 | 固定 3×3，无钥匙门 | 8 万 | 100% |
| 1 | 固定 5×5，无钥匙门 | 10 万 | 100%（背图：走的正是最短路） |
| 2 | 随机 5×5，无钥匙门 | 45 万 | 99%，步数/最优 1.18 |
| 3 | 随机 5×5，有钥匙门 | 8 万（接阶段 2） | 98%，步数/最优 1.30 |
| 4 | 随机 8×8，有钥匙门 | 10 万（接阶段 3） | 96%（采样）/ 85%（贪心） |
| 5 | 随机 5×5，有钥匙门，**地图观测** | 63 万（从零） | 98% |
| 6 | 随机 5–10 混合尺寸，有钥匙门，**地图观测** | 90 万（接阶段 5） | 见下表 |

阶段 0–4 是局部观测（四周 4 格），总共约 80 万步、CPU 二十分钟；阶段 5–6 换成地图观测（见下），每步慢一倍。

## 尺寸泛化基准（`bench.py`）

三个模型放在四个尺寸上统一评估。成功率，**采样 / 贪心**；括号里是成功局的步数÷最优：

| 模型 | 训练尺寸 | 5×5 | 8×8 | 12×12 | 16×16 |
|---|---|---|---|---|---|
| 阶段 3 局部观测 | 5 | 97 / 98 (1.4) | 84 / 80 (1.9) | 58 / 44 (2.4) | 43 / 27 (3.6) |
| 阶段 4 局部观测 | 8 | 98 / 97 (1.4) | **96** / 85 (1.8) | 70 / 54 (2.5) | **63** / 23 (3.4) |
| 阶段 6 地图观测 | 5–10 | **100 / 100** (1.3) | 93 / 81 (1.4) | **74** / 46 (1.7) | 47 / 23 (2.0) |
| 算法 agent | — | 100 (1.7) | 100 (2.2) | 100 (2.6) | 100 (3.2) |

三个结论：

**1. 评估必须用采样，不能用贪心。** 贪心（每步取 argmax）是确定性的，一旦进入 A→B→A→B 的循环就永远出不来；采样会随机打破循环。差距随尺寸急剧放大：阶段 4 在 16×16 上贪心 23%、采样 63%。早期用贪心报的数字都偏低，`eval.py` 现在默认采样。

**2. 地图观测没有带来预期的泛化优势。** 它的出发点是"把'哪里走过了'从 LSTM 里拿出来交给一张图，大迷宫上就不会忘"。结果：5×5 最好（100%），8×8 和 12×12 和阶段 4 基本持平，**16×16 反而更差**（47% vs 63%）。它的真实优势只有一个——成功时走得更短（1.4–2.0× vs 1.8–3.4×）。代价是每步慢一倍、CNN 不能继承局部观测的权重、要重新走一遍课程。在这个任务上**不值得**。

为什么没用？局部观测天然和尺寸无关——agent 看到的永远是四周 4 格；地图观测反而引入了新的尺寸依赖：25×25 窗口里"有内容的区域有多大"随迷宫变化，小迷宫上训出来的 CNN 到大迷宫上看到的是没见过的图案。混合尺寸训练能缓解，但 16×16 超出了训练范围（5–10），依然掉得厉害。

**3. 局部观测 + LSTM 的泛化比最初预想的好。** 只在 5×5 训过的阶段 3，零样本在 8×8 还有 84%；在 8×8 训过的阶段 4，零样本 16×16 有 63%。RL agent 成功时步数一直比算法 agent 少，因为它学到了迷宫生成器的统计规律（终点在右下角、钥匙偏爱死胡同）；算法 agent 不懂迷宫，只能按最近前沿机械搜索，但它的记忆是一个字典，不受尺寸限制，所以成功率永远 100%。

想继续往大尺寸推，比地图观测更可能有效的方向：直接在更大的尺寸上训（阶段 4 → 12 → 16 的课程）、加大 LSTM、或者在评估时结合简单的循环检测。

## PPO+LSTM 设计要点

- **局部观测不含绝对坐标**，agent 必须靠 LSTM 记忆来定位，否则 LSTM 没意义
- **地图观测**（阶段 5–6）：环境替 agent 维护一张只含"看见过的格子"的已探索地图，取以 agent 为中心的 25×25 窗口（6 通道：墙/地面/走过/终点/钥匙/门）给一个小 CNN，再接 LSTM
- **奖励**：终点 +1，钥匙 +0.3，新格子 +0.02（探索奖励，解决稀疏问题的关键），每步 −0.01，撞墙 −0.01
- **minibatch 以整条环境序列为单位**，保持时间顺序；更新时从 rollout 开始的 h₀ 重新前向
- **episode 边界重置隐状态**（`first` 掩码），采样和更新时都做，防止上一局记忆泄漏
- **超时**（truncated）用 γ·V(s_final) bootstrap，和真正到达终点区分开
- **课程学习**是关键：阶段 3 的钥匙门从零训会卡在稀疏奖励上，接着阶段 2 的探索策略训，起步就有 89%
